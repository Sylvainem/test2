## 方向一：學生成績管理系統 📊
### ——「讓 Excel 失業的第一步」

**一句話介紹**：拿 `students.csv` 開刀，做一個會讀檔、會算分、會吐報表的小工具，從此老師不用再按計算機按到手抽筋。

### 大綱
1. **前言：為什麼要自找麻煩？**
   - 手動算成績：慢、容易錯，還很容易算到懷疑人生
   - 目標：讓 Python 當免費助教，不領薪水也不會請假
2. **功能設計：這台機器會做什麼？**
   - 讀取 CSV（`open`、`csv` 模組上場打工）
   - 查成績、算平均 / 最高 / 最低分，誰考第一名一目了然
   - 把結果寫進新檔案，留下證據
3. **程式架構：把大象切成小塊**
   - 每個功能拆成一個函式，各自負責、互不推卸
   - 參數、回傳值、預設值，函式之間的「溝通禮儀」
4. **例外處理：程式也需要心理建設**
   - `FileNotFoundError`：檔案呢？檔案去哪了？
   - `ValueError`：有人把分數填成「很高」
   - `try / except / finally`：跌倒了要優雅地爬起來
5. **成果展示**：截圖為證，證明它真的會動（至少在我電腦上）
6. **結論與未來展望**：下一步加圖表、加介面，目標是讓 Excel 緊張一下

## 方向二：物件導向實作 + 單元測試 ☕
### ——「萬物皆可 class，連馬克杯也不放過」

**一句話介紹**：延續課堂上的 `Mug` 馬克杯，把生活中的東西（飲料店、購物車、圖書館）通通變成類別，再用 pytest 確認它們沒有偷偷壞掉。

### 大綱
1. **前言：什麼是物件導向？**
   - 簡單說就是：把世界變成一堆會做事的東西
   - 馬克杯有容量、會被倒滿，這就是屬性和方法
2. **需求分析：選一個你最熟的情境**
   - 推薦：飲料店點餐系統（半糖少冰，寫程式也要講究）
   - 列出有哪些物件、它們有什麼、會做什麼
3. **類別設計：幫物件辦身分證**
   - 畫類別圖，屬性和方法排排站
   - `__init__`（出生）、實例方法（日常）、`__str__`（自我介紹）
   - 資料驗證：容量不能是負數，這不是黑洞
4. **單元測試：不信任自己的程式是一種美德**
   - 用 pytest 寫測試（參考 `tests/test_mug.py`）
   - 正常情況、邊界值、亂輸入，三種情境都要考
   - 綠色 PASSED 是世界上最療癒的顏色
5. **成果展示**：程式碼片段，加上一整排測試通過的截圖
6. **心得反思**：測試抓到 bug 的那一刻，心情既感激又羞愧

## 方向三：AI 輔助程式開發的實踐與反思 🤖
### ——「我和我的 AI 同學」

**一句話介紹**：記錄這學期和 Claude Code、Gemini 一起寫作業、開分支、發 PR 的過程，老實檢討 AI 幫了多少忙、又闖了多少禍。

### 大綱
1. **前言：AI 來了，作業還要自己寫嗎？**
   - AI 程式助理崛起，學生的學習方式也跟著改變
2. **工具介紹：認識我的隊友們**
   - Claude Code / Gemini：會寫程式、會寫文件，偶爾也會一本正經地講錯
   - Git 三寶：分支（`class/xxxx`）、commit、Pull Request
3. **實作案例：AI 實戰紀錄**
   - 案例一：讓 AI 產教材（函式教學、例外處理筆記）
   - 案例二：讓 AI 幫忙寫程式和測試（`calc.py`、`mug.py`）
   - 案例三：跨界應用，連高雄、台南的旅遊行程都排好了
4. **分析比較：AI 到底靠不靠譜？**
   - 哪些地方要人工修正？（抓 AI 的錯也是一種學習）
   - 自己寫 vs. AI 寫：速度差多少？理解差多少？
5. **風險提醒：不能只會按 Enter**
   - 太依賴 AI、沒驗證就交、不小心把隱私資料丟給 AI
6. **結論**：AI 是學習夥伴，不是代寫槍手；方向盤還是要握在自己手上
